皮肤中心发布 0.4.19，与 dsh-web 全家桶 0.4.19 同版本发布。这一版有一处用户可见变更：官方插件列表里皮肤中心这一行的标题与灰色描述不再回落成 npm 包名和英文清单里的长描述，改由包内 `locale/en.json` 与 `locale/zh.json` 提供。另有一处契约收缩，`contracts/semantic-attrs-v1.md` 删掉已从全家桶下线的 `dsh-message-edit` 留下的三行。皮肤目录仍是 66 套，皮肤资产、Reviewed Skin Hooks 记录与运行时源码一个不动。

> **兼容性**：本版本没有破坏性变更，也没有需要手工迁移的改动：包名 `@linxin666/dsh-client-ui-skin-center`；宿主下限 `dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖仍是 `>=0.2.2-rc.2`，SDK 队列本版不动；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单只增不减，补上 `locale` 目录之后仍只内置 `blue-fantasy` 一套皮肤；v2 活跃状态文档的持久化文件名与键名；仍在使用的语义属性名（`data-dsh-skin`、`data-dsh-part`、`data-dsh-plugin`）；线协议字段——全部未改名。删掉的三行只属于已下线的插件，仓库里没有任何皮肤引用它们；老宿主不认识 locale 频道时也只是继续显示原来的包名，不会报错。`lib/` 重建后只有 `lib/client.js` 里的构建期版本串变化。

### 新功能

- 插件页的标题与描述改由包内提供（0a1eb5a）：官方插件列表按 `<package>/locale/<lang>.json` 的 `meta.title` 与 `meta.description` 渲染每一行的标题与灰色描述，先解析 `locale/en.json`，再枚举该目录下每个 `*.json` 并逐个走这个包自己的 `exports` 映射。皮肤中心此前没有这个频道，于是在插件页上显示的是 npm 包名与英文清单里那段长描述；本版补上 `locale/en.json`（`Skin center` / `Switch skins and wallpapers from one center.`）与 `locale/zh.json`（`皮肤中心` / `切换皮肤与壁纸的皮肤中心`）。
- 文件、`exports` 键与 npm 白名单必须同时成立（0a1eb5a）：这三处缺任何一处，整次元数据读取就失败并静默回落到包名，所以 `exports` 新增 `./locale/en.json` 与 `./locale/zh.json` 两个键，`files` 白名单新增 `locale` 目录——只写文件不写键，或者写了键却让 npm 把目录丢掉，用户看到的仍是旧回退。
- `icon` 沿用既有声明（0a1eb5a）：`package.json` 的 `icon` 仍是 `icon.svg`，`files` 白名单里也一直有它，本版不动它；新增的闸门把它一起锁住。
- 这份元数据有了闸门（0a1eb5a）：`tests/display-metadata.spec.ts` 断言两种语言的文件都在、磁盘上每个 `*.json` 都有对应的 `exports` 键且没有多余键、每份只带非空的 `title` 与 `description`、中文标题与描述都与英文不同且中文描述汉字不超过 20 个、`files` 收录 `locale` 目录与图标路径、图标是包内相对路径且扩展名在可渲染范围内。

### 契约收缩

- `dsh-message-edit` 退出语义属性契约（5cc38df）：这个插件是从全家桶整体移除的，不是原地弃用。它不在，就没有任何 DOM 会盖上契约里那一行 `data-dsh-plugin` 与两行 `data-dsh-part`（`entry`、`editor`），留着等于请皮肤作者去画一个不可能存在的面。三行删掉，分组标题按剩下的表重数：part 组从 99 行改到 97 行，plugin 组从 17 个改到 16 个。
- 没有选择保留或标注弃用（5cc38df）：契约的价值正是「运行时被盖上的东西」，而一行弃用记录在皮肤作者眼里仍然像还在盖。仓库里唯一的引用就是契约本身（其余命中都在冻结的发布说明里），所以没有皮肤选择器要清理，`pnpm skin-center:check` 与 `pnpm skin-hooks:check` 都不受影响。

### 其他改动

- 皮肤收录轮的记录（2cc077b）：`.agents/notes/implemented/process/2026-11-13-skin-intake-round.md` 记下 2026-11-13 这一轮的判断，PR `#108`（`remiel-starlit` 0.1.2）因两处阻塞级选择器缺陷退回作者修改，另 5 个停在 `CHANGES_REQUESTED` 的 PR 继续等作者提交。这一轮 `main` 上没有代码或皮肤版本变动，所以本版不新增皮肤。
- 版本对齐：`package.json` 的 `version` 对齐到 `0.4.19`，与 dsh-web 全家桶 0.4.19 同版本发布；本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明。
- `lib/` 只有一行跟着版本走：重建后 `lib/client.js` 里构建期烤进去的版本串从 `0.4.18` 变成 `0.4.19`，`lib/index.js`、`lib/css-safety.js`、`lib/css-safety-worker.js` 与 `lib/client.js.map` 逐字节相同，因为本版没有源码与皮肤资产改动。
- 目录规模：仓库内目录皮肤 66 套，npm 白名单仍只内置 `blue-fantasy`，其余全部作为市场内容按需安装；本版不改任何皮肤的 manifest 与令牌。

The skin center publishes 0.4.19, on the same version as the dsh-web family's 0.4.19. This release carries one user-visible change: on the official plugin list, the skin center row's title and grey description no longer fall back to the npm package name and the long English manifest description, and are served from the package's own `locale/en.json` and `locale/zh.json` instead. It also carries one contract tightening, where `contracts/semantic-attrs-v1.md` drops the three rows the removed `dsh-message-edit` left behind. The catalog stays at 66 skins, and the skin assets, the Reviewed Skin Hooks record and the runtime sources do not move.

> **Compatibility**: this release is not a breaking change and nothing has to be migrated by hand: the package name `@linxin666/dsh-client-ui-skin-center`; the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor, both still `>=0.2.2-rc.2` with the SDK cohort untouched in this release; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which only grows and still ships `blue-fantasy` as the only bundled skin once the `locale` directory is added; the persisted file name and keys of the v2 active-state document; the semantic attribute names still in use (`data-dsh-skin`, `data-dsh-part`, `data-dsh-plugin`); and the wire fields. The three deleted rows describe a plugin that has left the family and no skin in this repository references them, while an older host that does not know the locale channel simply keeps showing the previous package name instead of failing. `lib/` rebuilds with only the build-time version string inside `lib/client.js` changing.

### New Features

- The plugin page title and description now come from the package (0a1eb5a): the official plugin list renders each row's title and grey description from `<package>/locale/<lang>.json` (`meta.title` and `meta.description`), resolving `locale/en.json` first and then enumerating every `*.json` in that directory and resolving each one through the package's own `exports` map. The skin center had no such channel, so its row on the plugin page showed the npm package name and the long English manifest description; this release adds `locale/en.json` (`Skin center` / `Switch skins and wallpapers from one center.`) and `locale/zh.json` (`皮肤中心` / `切换皮肤与壁纸的皮肤中心`).
- The file, the `exports` key and the npm whitelist have to hold together (0a1eb5a): missing any one of the three makes the whole metadata read fail silently and fall back to the package name, so `exports` gains the `./locale/en.json` and `./locale/zh.json` keys and `files` gains the `locale` directory. A file without its key, or a key whose directory npm drops, leaves the user on the old fallback.
- `icon` keeps its existing declaration (0a1eb5a): the manifest's `icon` is still `icon.svg` and `files` has carried it all along, so this release does not move it; the new gate locks it in place alongside the locale channel.
- The metadata has a gate now (0a1eb5a): `tests/display-metadata.spec.ts` asserts that both language files exist, that every `*.json` on disk has its `exports` key and no key lacks a file, that each file carries only a non-empty `title` and `description`, that the Chinese title and description both differ from the English ones and the Chinese description stays within 20 Han characters, that `files` lists the `locale` directory and the icon path, and that the icon is a relative path inside the package with a renderable extension.

### Contract Tightening

- `dsh-message-edit` leaves the semantic attribute contract (5cc38df): the plugin was removed from the family outright rather than deprecated in place. With it gone, no DOM stamps the one `data-dsh-plugin` row and the two `data-dsh-part` rows (`entry`, `editor`) the contract still enumerated, so keeping them invites skin authors to style something that cannot exist. The three rows are deleted and the group headings are recounted against the remaining tables: the part group from 99 rows to 97, the plugin group from 17 owners to 16.
- Keeping or deprecating the rows was rejected (5cc38df): the value of the enum is exactly "what is stamped at runtime", and a deprecated row still reads as stamped to a skin author. The only references in the repository were the contract itself, with the remaining hits in frozen release notes, so no skin selector needed cleanup and `pnpm skin-center:check` and `pnpm skin-hooks:check` are unaffected.

### Other Changes

- The skin intake round is recorded (2cc077b): `.agents/notes/implemented/process/2026-11-13-skin-intake-round.md` writes down the call from 2026-11-13, where PR `#108` (`remiel-starlit` 0.1.2) went back to its author for two blocking selector defects while the five other PRs sitting at `CHANGES_REQUESTED` keep waiting for new commits. That round moved no code and no skin version on `main`, which is why this release adds no skin.
- Version alignment: `version` in `package.json` aligns to `0.4.19` on the same version as the dsh-web family's 0.4.19; this repository publishes one package, so that field is the only version declaration in it.
- `lib/` moves by one line, with the version: after the rebuild the version string baked into `lib/client.js` at build time reads `0.4.19` instead of `0.4.18`, while `lib/index.js`, `lib/css-safety.js`, `lib/css-safety-worker.js` and `lib/client.js.map` rebuild byte-identical because neither the sources nor the skin assets changed in this release.
- Catalog size: 66 catalog skins in the repository, while the npm whitelist still ships `blue-fantasy` only and every other skin is market content installed on demand; this release changes no skin's manifest or tokens.
